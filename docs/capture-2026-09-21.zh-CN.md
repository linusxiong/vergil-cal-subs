普通第三方网页不能因为打开学校登录页就读取学校页面中的 Token；手机 App 的系统浏览器登录也不会自动获得其他客户端的凭据。此前能够观察请求依赖本机经用户授权的 CDP 诊断，并不是网页可用的产品登录接口。

目前工作流是用户主动把自己的 Token 交给可信部署，服务只请求本人课表、存储快照。它不等于正式注册的只读 OAuth 授权；学校客户端发放的宽权限 Token、第三方接入许可及托管要求仍是部署者需要确认的外部边界。

## 当日后续线上验证

用户授权的生产请求暴露了两个兼容性问题：Cloudflare 实际运行时拒绝 `redirect: "error"`，在请求发出前抛出 TypeError；学校 JSON:API 接口对仅接受 `application/json` 的请求返回 406。现使用 `redirect: "manual"` 并拒绝所有非成功响应，不跟随重定向；人员与课程 API 的 Accept 改为 `application/vnd.api+json, application/json`，OAuth 端点继续使用 `application/json`。错误响应仅包含固定端点路径、HTTP 状态或安全错误类别，不含上游响应、查询参数、身份或凭据。

修复后，Cloudflare 生产接口创建返回 201，ICS 与管理读取返回 200，临时验证订阅撤销返回 204，撤销后 ICS 返回 404。凭据与真实课程内容没有写入仓库或诊断文件。此次使用有效 Access Token，未触发刷新，不能据此确认 Refresh Token grant。
